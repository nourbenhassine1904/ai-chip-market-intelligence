# Préparation de soutenance — Phase 9B

Les réponses ci-dessous décrivent les résultats gelés ; aucune nouvelle estimation n’a été effectuée pour le rapport.

1. **Pourquoi NVDA, AMD et SOXX ?** NVDA est la cible fixée avant modélisation ; AMD et le fonds sectoriel SOXX fournissent le contexte multivarié. SOXX peut inclure une exposition aux entreprises étudiées : ce n’est pas une source indépendante. Sources : `docs/protocol.md`, `docs/data_dictionary.md`.
2. **Que signifie d=1 ?** Une différence du log-prix suffit selon les diagnostics TRAIN : ADF rejette la racine unitaire sur les log-rendements et KPSS ne rejette pas leur stationnarité. Cela ne prouve ni normalité ni homoscédasticité. Sources : `outputs/tables/phase2_stationarity_tests.csv`, `docs/phase3a_arima_identification.md`.
3. **Comment éviter la fuite temporelle ?** Split chronologique 1980/220 ; décisions et scalers sur TRAIN ; folds internes purgés pour les réseaux ; paramètres gelés avant TEST. Sources : `docs/phase6_protocol.json`, `docs/phase7_final_evaluation_protocol.json`.
4. **Pourquoi l’ARIMA identifié n’est-il pas le modèle final ?** Les candidats non triviaux n’atteignent pas les gains requis lors de la validation interne. Le lock est ARIMA(0,1,0) sans drift sur log-prix, distinct du modèle diagnostiqué de Phase 3A. Sources : `outputs/tables/phase3b_locked_arima_model.csv`, `docs/phase3b_arima_validation.md`.
5. **Pourquoi VAR(9), alors que les critères proposent VAR(1) ?** VAR(1) conserve une autocorrélation résiduelle ; seuls les ordres 9 et 10 passent les diagnostics, et la règle préfère le plus petit admissible. Source : `docs/phase4_var_vecm.md`.
6. **Granger démontre-t-il une causalité économique ?** Non. C’est une précédence prédictive conditionnelle dans le système. Après Holm, SOXX→NVDA et SOXX→AMD restent significatifs ; cela n’identifie pas un choc structurel. Source : `docs/phase4_var_vecm.md`.
7. **Pourquoi ne pas estimer de VECM ?** Johansen retient le rang zéro dans la spécification principale et les sensibilités retenues. Le gate préétabli ferme donc la branche VECM. Source : `outputs/tables/phase4_johansen_rank_comparison.csv`.
8. **Pourquoi GARCH Normal plutôt que Student-t ?** Student-t améliore AIC/BIC, mais ne remplit pas le gain de diagnostic de queue requis dans les deux langages. Le lock reste Normal, avec une limite explicite sur les queues. Sources : `outputs/tables/phase5_garch_model_comparison.csv`, `docs/phase5_garch.md`.
9. **Que prédit GARCH ?** La variance conditionnelle des innovations, exprimée ici en points de pourcentage de rendement au carré ; son sigma quotidien ne constitue ni un prix ni une volatilité historique annualisée. Source : `outputs/tables/phase5_volatility_forecast_train_end.csv`.
10. **Quels réseaux ont été retenus ?** Les configurations C de LSTM et GRU, avec une sortie directe à dix horizons, seed 42 et scalers TRAIN. Leur performance interne puis finale défavorable est conservée. Sources : `outputs/tables/phase6_locked_lstm.csv`, `outputs/tables/phase6_locked_gru.csv`.
11. **Comment les cinq modèles sont-ils comparés ?** Sur 211 origines communes à h=5 et h=10, en USD ajustés NVDA ; poids et paramètres restent gelés, les états peuvent intégrer les observations passées disponibles. Source : `docs/phase7_final_evaluation_protocol.json`.
12. **Pourquoi Naive gagne-t-il malgré la RMSE ARIMA à h=10 ?** ARIMA a une RMSE légèrement plus basse à h=10, mais manque le gain moyen de 1 %, la contrainte MAE et le support DM requis. Aucun challenger ne passe l’ensemble des conditions. Sources : `outputs/tables/phase7_recommendation_checks.csv`, `outputs/tables/phase7_final_model_recommendation.csv`.
13. **Comment interpréter un non-rejet de Diebold–Mariano ?** Il ne prouve pas l’égalité. Le test compare les pertes au carré, tient compte des horizons recouvrants et applique Holm séparément aux quatre comparaisons contre Naive par horizon ; l’avantage ARIMA n’est pas établi. Source : `outputs/tables/phase7_diebold_mariano.csv`.
14. **Que prouve l’audit du LLM ?** Les 35 affirmations sélectionnées sont soutenues par les sources fournies. L’audit n’est ni aveugle ni indépendant ; la baseline humaine a été assistée, et les métadonnées de génération exactes manquent. Sources : `docs/phase8_llm_analysis.md`, `llm/human_analysis/phase8_hallucination_audit.csv`.
15. **FAST satisfait-il la reproduction complète ?** Non. FAST vérifie les artefacts et leurs métriques. FULL sur machine vierge reste PARTIAL : notebook orchestrateur, snapshots, vrais scripts R/Python, packages CPU et gate Phase 7 isolé sont à préparer puis tester, sans écraser les résultats ou le LLM. Sources : `docs/reproduction_guide.md`, `docs/final_requirements_checklist.md`.
